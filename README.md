# wuli娟娟

柔和粉色风格的学校账单分类桌面工具。EXE 已包含 Python 运行环境，普通用户无需安装 Python，也无需安装 Excel 才能生成账单。

Windows 本地 Python 桌面程序。选择源账单的第一个 sheet，按“客户名”生成每校一个 Excel，每个文件包含：全部明细、总计表、老师明细、学生明细；该校有活动单时再增加活动单明细。

## 环境与安装

- Windows 10/11；Python 3.11 或以上（python.org 标准安装版，包含 Tkinter，安装时勾选 Add Python to PATH）。当前已使用 Python 3.14.6 创建 `.venv` 并安装依赖。
- 仅依赖 openpyxl 3.1.5；首次安装需要网络。运行无需网络，也无需安装 Excel；查看和重算公式建议使用 Excel/WPS。
- 新电脑：安装 Python，然后双击 `install.bat`。不要把旧电脑的 `.venv` 直接复制使用。

命令行安装：
```powershell
cd D:\project\prictice\bill-splitter
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 使用方法

1. 双击 `start.bat`，或执行 `.\.venv\Scripts\python.exe app.py`。
2. 选择源 `.xlsx` 文件和输出目录。
3. 选择金额口径，默认“销售金额(元)”，可改为“下单金额(元)”。
4. 点击“生成全部学校账单”。每次生成独立时间戳目录，不覆盖已有文件。
5. 查看每校四个或五个 sheet，同时检查 `待核对记录.csv` 和 `运行报告.json`。
   也可点击程序底部“查看核对报告”，或双击输出目录的 `核对报告.html`，在浏览器离线查看金额、学校文件和可搜索的异常记录。异常位置使用源 Excel 工作表名称和左侧行号（包含表头），可按提示用 Ctrl+G 定位。
6. 如有待核对行，在源账单副本中修正客户名及对应分类字段后重新生成。分类总计只包含已分类记录。

源表第一行必须包含唯一表头：客户名、收货地址、配送日期、选定金额列。读取其他原始列并保留；选定日期和金额会标准化。支持 Excel 日期和 yyyy-mm-dd、yyyy/mm/dd、yyyy.mm.dd 文本。仅支持 xlsx。

分类方式按每所学校判断：若“对象名称”列任一记录包含“活动单”，该校全部记录仅按对象名称中的“老师”“学生”“活动单”分类，总计表增加活动单列并计入总计；空值、未知值和多类冲突进入待核对。没有活动单（包括缺少对象名称列的旧账单）时，沿用收货地址分类。对象名称列存在时须唯一。

地址分类的老师关键词：教师、成人、职工、老师。学生关键词：幼儿、学生。匹配整个收货地址文本；同时命中两类或均未命中为待核对。空客户名不生成学校文件，但写入异常清单。合计/总计且无日期、地址的行视为汇总行跳过。原始公式读取 Excel 已保存的缓存值；缓存缺失的金额会报错，需先用 Excel/WPS 重算并保存。

客户名仅用于学校分组。使用地址分类时排除机构名称中的“幼儿园”，避免“某幼儿园（成人）”误判为两类冲突；独立的“幼儿”备注仍归学生。

输出文件名采用实际最早/最晚配送日期（含年份），并增加编号避免非法字符清洗后重名。不是固定自然月起止日期。导出明细删除“序号”列，其余原始列和行顺序保留；全部工作表（包括表头、合计行）行高为17.25；总计表日期升序，底部有 SUM 公式。无分类数据时老师/学生明细仍保留表头。

## 常见问题

- 缺少表头：确认数据位于第一个 sheet，表头在第一行，名称与界面所选金额列一致。
- 金额或日期无效：按错误提示定位源行，修正副本后重新运行。
- PermissionError：关闭占用输出文件的 Excel，或选择有写入权限的文件夹。
- 公式暂时为空：openpyxl 不计算公式，Excel/WPS 打开后重算；精确核对金额见运行报告。
- `.xls` 文件：先另存为 `.xlsx`。

## EXE 安装、打包和更新（0.3.0）

普通使用者不需要安装 Python。首次从本项目 GitHub Releases 下载 `wuli娟娟.exe`，放在自己有写入权限的文件夹，双击运行。支持 Windows 10/11 64 位。不要直接在压缩包内运行。

界面右上角显示当前版本，点击“检查更新”。发现更高的正式版本后确认下载，程序校验 SHA256，随后关闭旧程序、替换并重新启动。旧程序保存在同目录 `.previous` 文件中。生成账单时禁用更新；不会上传账单。源码运行时只下载 EXE 并打开所在目录，不替换源码。检查更新需要能访问 GitHub；无网络不影响账单功能。校验用于检测下载损坏，不代替代码签名；EXE 暂未签名。

### 本机打包

先运行 install.bat，再双击 build.bat。结果位于 `dist/wuli娟娟.exe`。开发依赖和 PyInstaller 版本在 requirements-build.txt 中。

### GitHub Actions 发布

仓库地址：https://github.com/WEBNSNM/bill-splitter 。自动更新当前使用公开仓库 Releases，不在程序内嵌入私人令牌。

1. 将这些项目修改提交并推送到 GitHub。
2. Actions 页面选择 Windows EXE → Run workflow，可先试打包；结束后下载 `wuli娟娟-Windows` 制品。手动运行不会发布正式版本；想测试自动更新，需把 v0.3.1 的 EXE 和校验文件手动附加到 v0.3.1 GitHub Release。
3. 正式发布前修改 `bill_splitter/version.py` 中 VERSION，并更新 CHANGELOG.md，例如下一版改为 0.3.1。
4. 提交推送代码，再执行以下命令（首次当前版使用 v0.3.0）：

```powershell
git tag v0.3.0
git push origin v0.3.0
```

5. 标签触发测试、Windows 打包、SHA256 生成、GitHub Release 发布。标签必须与代码 VERSION 完全一致。发布资产名称为 `wuli娟娟.exe` 和 `wuli娟娟.exe.sha256`，不要手动更改名称。
6. 下一版用 v0.3.1 等新标签，不重用旧标签。已安装旧 EXE 的用户点击检查更新即可获取新版。

首次发布前，检查更新可能提示“尚无公开正式版本”。仓库改名时需同时更新 version.py 中 GITHUB_REPOSITORY。安装目录无法写入时，可手动下载并移至可写目录。

完整线上验收：发布 0.3.0 并运行该 EXE，再发布 0.3.1，点击旧版检查更新，确认重启后版本显示 0.3.1、账单生成正常、旧版备份存在。当前本地测试不等同于完成此线上验收。
